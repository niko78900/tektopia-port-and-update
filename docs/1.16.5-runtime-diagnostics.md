# TekTopia 1.16.5 Runtime Diagnostics

## Crash Reports

Launcher `Error Code: -1` is only the outer wrapper. Use the newest file in:

- `%APPDATA%\.minecraft\crash-reports\`
- `%APPDATA%\.minecraft\logs\latest.log`

For the development run directory, use:

- `port-1.16.5/run/crash-reports/`
- `port-1.16.5/run/logs/latest.log`

## Renderer Failures

Forge 1.16 copies mod entity render factories during client setup. TekTopia renderer registration must happen directly in `FMLClientSetupEvent`, not inside delayed `enqueueWork`, or custom entities can enter the world with no renderer and crash in `EntityRendererManager.shouldRender`.

The client log should include:

```text
Registered 23 TekTopia entity renderers during client setup
TekTopia visual coverage check: complete=...
TekTopia animation coverage check: present=...
```

If a CraftStudio model or animation fails at runtime, the renderer now logs the failing asset path and phase, disables that CraftStudio renderer, and falls back to the vanilla biped model instead of crashing the render thread.

## Useful QA Commands

Run these in-game after loading a world:

```text
/tektopia_port asset_inventory strict
/tektopia_port spawn_test_worker farmer
/tektopia_port spawn_test_worker necromancer
```

Keep the newest crash report and `latest.log` when reporting a crash. The line above the exception usually identifies whether the failure came from renderer registration, CraftStudio parsing, texture lookup, particles, or sounds.
